# Вердикт ревью — шаблон

**Назначение.** Ответ ревьюера автору: сливать или нет и почему. Заменяет разбросанные комментарии
одним читаемым итогом — иначе автор собирает вердикт сам, по десяти веткам обсуждения, и собирает
неверно.

**Автор:** ревьюер. **Принимает:** автор MR (точка `КТ5`).

## Требования

- **Вердикт — одно из трёх и в первой строке:** сливать, доработать, отклонить. Вердикт, который надо
  вычислять из текста, вычисляется неправильно.
- **Замечание = класс + место + чем проверить.** Замечание без способа проверки — мнение, и спор о нём
  не сходится: каждая сторона остаётся при своём, а решает громкость.
- **Блокирующие отделены от необязательных.** Смешанные в один список, они превращают ревью в торг: автор
  чинит простое и оставляет главное.
- **Перечень проверенного обязателен** — что именно смотрел. Ревью без перечня выглядит одинаково и
  когда всё проверено, и когда просмотрен дифф по диагонали.
- **Спор о вкусе решается ссылкой на норму.** Нормы нет — замечание снимается либо заводится норма.
  Третьего не бывает; иначе ревью становится способом навязать привычку.
- **Снятие находки безопасности — не за автором.** Даже если автор объяснил убедительно.
- **Что не проверял — записывается.** Ревьюер, промолчавший о непроверенном, оставляет автора в
  уверенности, что проверено всё.

## Шаблон

```markdown
# Вердикт ревью <MR>: сливать / доработать / отклонить

> **Ревьюер:** <имя> | **Дата:** <...> | **Постановка:** <ссылка>

## Что проверял
| Пункт | Проверено | Замечание |
|---|---|---|
| соответствие сценариям приёмки | да | — |
| границы: нет ли сверх постановки | да | см. Б1 |
| контракт | не применимо | |
| миграция и откат | | |
| тесты падают на старом коде | | |
| наблюдаемость | | |
| безопасность | | |
| документация тем же MR | | |

## Блокирующие
| № | Класс | Место | В чём дело | Чем проверить исправление |
|---|---|---|---|---|
| Б1 | | <файл:строка> | | |

## Необязательные
| № | Класс | Место | В чём дело |
|---|---|---|---|

## Чего не проверял
| Что | Почему |
|---|---|

## Находки для бэклога
| Находка | Класс | Заведена |
|---|---|---|
```

## Критерий передачи (проверяет ревьюер)

- [ ] вердикт стоит в первой строке и он один из трёх;
- [ ] у каждого блокирующего замечания назван способ проверки исправления;
- [ ] блокирующие отделены от необязательных;
- [ ] перечень проверенного заполнен целиком, включая «не применимо»;
- [ ] раздел «чего не проверял» заполнен или пуст осознанно;
- [ ] ни одно замечание не опирается на вкус без ссылки на норму.

## Критерий приёмки (проверяет автор)

- [ ] я понимаю, что именно чинить и как покажу, что починил;
- [ ] по каждому блокирующему замечанию у меня есть проверяемый способ закрытия;
- [ ] замечаний «сделай как я привык» без ссылки на норму нет — а если есть, я их оспариваю ссылкой на это правило.
