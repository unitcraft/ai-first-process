# Миграция данных — шаблон

**Назначение.** Описание изменения схемы или данных и порядка его применения. Миграция — единственный
шаг процесса, который **необратим по умолчанию**: код откатывается версией, данные нет. Отсюда все
требования ниже.

**Автор:** бэкенд-разработчик. **Принимает:** ревьюер и DevOps (точка `КТ3`, применяется в `КТ8`).

## Требования

- **Вперёд-совместимость обязательна.** Старая версия кода должна работать с новой схемой хотя бы один
  выпуск: иначе выкатка становится атомарной операцией «код + схема», а такой атомарности не бывает.
  Практически это означает разбиение: сначала добавить, потом переключить чтение, потом удалить — три
  выпуска, а не один.
- **Откат описан и проверен прогоном.** Не «в теории обратима», а прогнана на копии структуры. Откат,
  не проверенный прогоном, — это текст.
- **Потеря данных названа явно.** Если миграция теряет что-то (сужение типа, удаление колонки), это
  пишется словами и требует отдельного разрешения владельца продукта. Молчаливая потеря — самый дорогой
  из возможных дефектов, потому что необнаружим до момента, когда данные понадобились.
- **Объём и время оценены на реальном размере.** Миграция, идущая три минуты на тестовом наборе, может
  идти три часа на проде и блокировать таблицу. Замер делается на копии прод-структуры с
  сопоставимым объёмом.
- **Идемпотентность:** повторный запуск не ломает и не дублирует. Прерванная миграция — норма, а не
  исключение.
- **Применение — отдельный шаг выкатки**, не побочный эффект старта приложения. Приложение, мигрирующее
  на старте, делает это в момент, когда его никто не наблюдает, и во всех экземплярах одновременно.

## Шаблон

```markdown
# Миграция <имя>

> **Статус:** черновик / утверждена <дата> / применена на <контур> <дата>
> **Задача:** <ссылка> | **Автор:** <имя>

## Что меняется
| Объект | Было | Стало |
|---|---|---|

## Класс изменения
- [ ] только добавление (вперёд-совместимо)
- [ ] переключение чтения (требует, чтобы предыдущий выпуск уже был на месте)
- [ ] удаление (требует, чтобы переключение прошло и старый код снят)

## Потеря данных
<«Нет» — или что именно теряется, и кто это разрешил: имя, дата.>

## Порядок применения
1. <шаг>
2. <шаг>

## Откат
| Шаг | Команда | Проверен прогоном |
|---|---|---|

## Замер
| Величина | На тестовом наборе | На копии прод-структуры |
|---|---|---|
| время | | |
| объём затронутых строк | | |
| блокировки | | |

## Идемпотентность
<Что произойдёт при повторном запуске и при запуске на половине применённой миграции.>
```

## Критерий передачи (проверяет автор)

- [ ] класс изменения назван, и разбиение на выпуски соответствует классу;
- [ ] откат прогнан на копии структуры, вывод приложен;
- [ ] потеря данных названа словами: «нет» или что именно и с чьего разрешения;
- [ ] замер сделан на сопоставимом объёме, а не на тестовом наборе;
- [ ] повторный запуск проверен прогоном.

## Критерий приёмки (проверяют ревьюер и DevOps, `КТ3`)

- [ ] **ревьюер:** старая версия кода работает с новой схемой, либо назван выпуск, в котором это перестаёт требоваться;
- [ ] **DevOps:** я могу применить это отдельным шагом и откатить по написанному;
- [ ] **DevOps:** время применения приемлемо для окна выкатки;
- [ ] потеря данных либо отсутствует, либо разрешена поимённо.
