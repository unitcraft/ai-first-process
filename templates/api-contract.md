# Контракт — требования и шаблон описания

**Назначение.** Договор между поставщиком и потребителем данных: HTTP-API, событие, очередь. Сам
контракт — машинно-читаемая схема в репозитории контрактов; этот файл задаёт **требования к нему и
форму сопроводительного описания**, по которому его принимают.

**Автор:** разработчик поставщика. **Принимает:** ревьюер и **потребитель контракта** (ворота `G2`).

## Требования

- **Контракт первым, до кода.** Контракт, дописанный после реализации, описывает реализацию, а не
  договорённость: он перестаёт быть инструментом согласования и становится документацией по факту.
- **Клиенты и схемы генерируются из контракта**, не пишутся руками. Рукописный клиент расходится с
  контрактом молча, и расхождение обнаруживает потребитель в проде.
- **Версия и совместимость названы явно.** Изменение делится на три класса, и класс определяет порядок:
  добавление необязательного поля — совместимо; изменение смысла или типа — несовместимо и требует новой
  версии; удаление — несовместимо и требует срока жизни старой версии.
- **Ошибки — часть контракта.** Перечень кодов отказа с условием возникновения. Контракт, описывающий
  только успех, заставляет потребителя угадывать отказы.
- **Пример запроса и ответа обязателен** — по одному на каждый исход, включая отказы. Пример ловит
  недоразумения, которые схема пропускает.
- **Потребитель назван поимённо.** Контракт без известного потребителя нельзя принять: неизвестно, кому
  он подходит.
- **Идемпотентность названа** для всего, что меняет данные: как потребитель повторяет запрос, не создав
  вторую сущность.

## Шаблон описания к контракту

```markdown
# Контракт <имя>, версия <X.Y.Z>

> **Статус:** черновик / утверждён <дата> | **Схема:** <ссылка на файл схемы>
> **Поставщик:** <модуль> | **Потребители:** <модуль, имя ответственного>

## Что изменилось
| Изменение | Класс | Действие потребителя |
|---|---|---|
| <добавлено поле X> | совместимо | ничего |
| <изменён тип Y> | несовместимо | обновиться до <дата> |

## Исходы
| Исход | Код | Когда возникает | Что делать потребителю |
|---|---|---|---|
| успех | | | |
| отказ: нет прав | | | |
| отказ: не найдено | | | |
| отказ: неверные данные | | | |

## Идемпотентность
<Ключ, срок его действия, поведение при повторе. Или: «операция только читает».>

## Примеры
<По одному примеру запроса и ответа на каждый исход.>

## Срок жизни предыдущей версии
<До какой даты поддерживается и кто её ещё вызывает.>
```

## Критерий передачи (проверяет автор)

- [ ] схема лежит в репозитории контрактов и проходит валидацию;
- [ ] у каждого изменения назван класс совместимости;
- [ ] перечислены все исходы, включая отказы, и у каждого пример;
- [ ] названа идемпотентность для операций записи;
- [ ] клиенты сгенерированы из схемы, рукописных нет;
- [ ] потребители названы поимённо и извещены.

## Критерий приёмки (проверяют ревьюер и потребитель, `G2`)

- [ ] **потребитель:** мне этого достаточно, чтобы реализовать свою сторону без вопросов автору;
- [ ] **потребитель:** названный класс совместимости совпадает с тем, как это ляжет на мой код;
- [ ] **ревьюер:** отказы описаны, а не только успех;
- [ ] **ревьюер:** срок жизни предыдущей версии назван, и её вызывающие перечислены.
