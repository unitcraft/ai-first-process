# Модель угроз — шаблон

**Назначение.** Ответ на вопрос «что может пойти не так со стороны злоумышленника или ошибки прав» для
одного модуля. Обновляется **при изменении границ модуля**, а не по расписанию: модель, обновляемая по
календарю, описывает прошлый модуль.

**Автор:** разработчик модуля. **Принимает:** безопасность (ворота `G2`).

## Требования

- **Границы модуля названы первыми:** что внутри, что снаружи, где проходит доверие. Без границы
  перечень угроз бесконечен и потому бесполезен.
- **Входы перечислены все:** внешние запросы, события, файлы, задания по расписанию, административные
  операции. Забытый вход — забытая угроза, и обычно это административная операция.
- **Каждая угроза с мерой и с проверкой меры.** Мера без проверки — намерение: «валидируем ввод» ничего
  не значит без теста, который это подтверждает.
- **Персональные данные отдельно:** какие, где хранятся, срок, как обезличиваются в нижних контурах,
  как исполняется отзыв согласия. Это то, что спрашивают первым при внешней проверке.
- **Обход прав — обязательная угроза в перечне**, и её проверка ручная: сканеры её не находят.
- **Принятый риск записывается как принятый**, с именем принявшего и сроком пересмотра. Ненаписанный
  принятый риск через полгода читается как недосмотр.

## Шаблон

```markdown
# Модель угроз: <модуль>

> **Статус:** черновик / принята <дата> | **Пересмотр при:** изменении границ модуля
> **Автор:** <имя> | **Принял (безопасность):** <имя, дата>

## Границы
| Внутри модуля | Снаружи | Где граница доверия |
|---|---|---|

## Входы
| Вход | Кто вызывает | Аутентификация | Права |
|---|---|---|---|
| <HTTP-эндпоинт> | | | |
| <событие> | | | |
| <задание по расписанию> | | | |
| <административная операция> | | | |

## Угрозы и меры
| Угроза | Последствие | Мера | Чем проверена мера |
|---|---|---|---|
| обход прав: <как> | | | ручной кейс <ссылка> |
| подмена данных: <как> | | | тест <имя> |
| утечка через логи | | | страж <имя> |

## Персональные данные
| Что | Где | Срок хранения | Обезличивание в нижних контурах | Отзыв согласия |
|---|---|---|---|---|

## Принятые риски
| Риск | Почему принят | Принял | Пересмотр до |
|---|---|---|---|
```

## Критерий передачи (проверяет автор)

- [ ] границы модуля названы, включая границу доверия;
- [ ] перечислены все входы, включая расписание и административные операции;
- [ ] у каждой угрозы есть мера и **чем эта мера проверена**;
- [ ] обход прав присутствует в перечне угроз;
- [ ] персональные данные описаны или указано «модуль их не обрабатывает».

## Критерий приёмки (проверяет безопасность, `G2`)

- [ ] перечень входов совпадает с тем, что я вижу в контракте и коде;
- [ ] у каждой меры есть проверка, а не намерение;
- [ ] ручной кейс на обход прав попал в релизный набор;
- [ ] принятые риски названы поимённо и со сроком пересмотра.
