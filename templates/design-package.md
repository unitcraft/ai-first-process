# Дизайн-пакет — требования и шаблон описи

**Назначение.** То, что дизайнер передаёт фронтенд-разработчику. Пакет считается пакетом, только если
по нему можно собрать экран, **не задавая вопросов**. Пакет без состояний отказа даёт половину
возвратов на точке `КТ6` — и это самая частая поломка передачи между этими двумя ролями.

**Автор:** дизайнер. **Принимает:** фронтенд-разработчик (точка `КТ2`).

## Требования

- **Все состояния, а не только успешное.** Обязательны: обычное, пусто, загрузка, ошибка загрузки,
  отказ доступа, предельно длинные значения, частичные данные. Разработчик, не получив состояние,
  придумает его сам — и придумает иначе, чем ожидал дизайнер.
- **Токены, а не значения.** Цвета, отступы, типографика — именами из дизайн-системы. Пакет,
  описанный конкретными цветами, ломает тему при первом изменении системы.
- **Компоненты названы существующими.** Каждый элемент либо ссылается на компонент библиотеки, либо
  помечен как новый — и тогда новый заводится **в библиотеку**, а не в экран.
- **Поведение, а не только вид:** что происходит при нажатии, куда уходит фокус, что с клавиатуры, что
  на узком экране.
- **Контрольные ширины названы** — те, на которых проверяется вёрстка. Ширина, которой нет в системе,
  в пакете не используется: разработчик подгонит под неё, а тест проверит другую.
- **Тексты — окончательные**, включая сообщения об отказах. Заглушка вида «текст будет» превращается в
  отдельную задачу после приёмки.

## Шаблон описи пакета

```markdown
# Дизайн-пакет: <экран или сценарий>

> **Статус:** черновик / передан <дата> | **Задача:** <ссылка>
> **Дизайнер:** <имя> | **Принял:** <имя, дата>

## Состояния
| Состояние | Макет | Текст |
|---|---|---|
| обычное | <ссылка> | |
| пусто | | |
| загрузка | | |
| ошибка загрузки | | |
| отказ доступа | | |
| предельные значения | | |

## Компоненты
| Элемент | Компонент библиотеки | Новый |
|---|---|---|

## Токены
<Перечень использованных токенов. Конкретных значений цвета и размера в пакете нет.>

## Поведение
| Действие | Что происходит |
|---|---|
| нажатие <элемент> | |
| клавиатура | |
| узкий экран | |

## Контрольные ширины
<Перечень из дизайн-системы. Других не используется.>
```

## Критерий передачи (проверяет дизайнер)

- [ ] все шесть состояний присутствуют или явно помечены как неприменимые с причиной;
- [ ] каждый элемент сопоставлен компоненту библиотеки либо помечен новым;
- [ ] конкретных значений цвета и размера в пакете нет — только токены;
- [ ] тексты окончательные, включая сообщения об отказах;
- [ ] контрольные ширины взяты из дизайн-системы.

## Критерий приёмки (проверяет фронтенд-разработчик, `КТ2`)

- [ ] я могу собрать экран по этому пакету, не задавая вопросов;
- [ ] мне не нужно придумывать ни одно состояние;
- [ ] новые компоненты, если они есть, я завожу в библиотеку — и это согласовано;
- [ ] названные ширины совпадают с теми, что проверяют тесты.
